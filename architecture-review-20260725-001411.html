ServePlan = {serve-from-storage | stream-and-cache | redirect}. Handler turns it into c.File/c.Redirect.

Problem

The cache-miss pipeline (storage → fileCache → indexCache → upstream → stream+store → headers → redirect) is inlined across three handler methods, mixing policy, coordination, and gin transport — with two overlapping dedup mechanisms (singleflight + a hand-rolled downloadCoordinator).

Solution

Extract a PackageFileService whose interface returns a ServePlan value instead of writing to gin.Context. One dedup mechanism inside; the handler only translates the plan to HTTP.

  • Locality: miss-pipeline lives in one module
  • Interface returns a result, not a side effect
  • Test the decision tree without gin
  • One dedup path, not two racing ones
  • Timeout / redirect policy stops leaking into transport

C · Narrow the Storage interface; type the not-found

Strong ports & adapters

Problem

Backend-specific methods sit on a shared interface as stubs, so callers runtime-assert and branch on a boolean; not-found is a stringly-typed, per-backend convention, and tiered.go can't tell a 404 from a real L1 failure — it silently masks both as a miss.

Solution

Keep a small core Storage; move zero-copy and presign behind opt-in capability interfaces adapters implement only when real. Add a sentinel ErrNotFound every adapter returns.

  • Interface shrinks; behaviour stays
  • Capability seam replaces boolean branch
  • Fixes real bug: tiered masks L1 errors
  • Fake file:// presign stub disappears
Also folds in: StreamingGet writes the body before returning *ObjectInfo, so headers set afterward are dropped once the response is flushed — reshape it to hand back metadata before the body.

Problem

Struct embedding means the server's busiest reads (GetFilePath, StreamingGet) fall through to LocalStorage and never touch RecordAccess — a hot file reads as cold and can be evicted mid-serve. The evictor also does raw os.Remove with a shadow size counter, needing a reconciliation loop to patch the drift.

Solution

Make LRULocalStorage wrap LocalStorage through the seam (not embed it) so every method records access, and evict via Delete. Then consider one eviction-policy module the four hand-rolled LRUs share.

  • Fixes real bug: eviction under active use
  • Size counter stops drifting from disk
  • Four LRUs → one policy module
  • Seam enforced, not bypassed by embedding

Tackle first

B — Collapse the download path into a serving module

It sits on the hottest path in the commit history (the Gin migration, serveFromStorageOptimized, tiered storage all land here) and it is where locality is worst: policy, coordination, and transport are tangled across three methods with two racing dedup mechanisms. A PackageFileService returning a ServePlan gives the miss-pipeline one home and one test surface — and makes candidates C and E safe to test through it.

Cheapest warm-up first: candidate A is pure deletion — no design needed, and it clears the streaming noise before you reshape the path.
